## 一、一次性设置清单

| # | 项 | 具体做法 | 为什么 |
|---|---|---|---|
| 1 | **Unity 版本** | 装一个 **LTS（长期支持）版**，**把版本号写下来**（例如 `6000.x.y LTS`），**整个项目周期内不升级** | 升级 Unity 是学生项目最常见的"工程突然打不开"原因 |
| 2 | **渲染管线** | 建项目时选 **URP** 模板（或后期升级到 URP） | **HD-2D 的"高级感"完全来自 URP 的后处理**，这是硬性前提 |
| 3 | **版本管理** | 装 **GitHub Desktop**（图形界面），建一个**私有**仓库 | 零基础不要用命令行 Git；但**一定要用**，否则丢工程是必然事件 |
| 4 | **.gitignore** | 用下面第七节的 Unity 版本 | 否则仓库会被上百 MB 的缓存撑爆 |
| 5 | **备份** | 除 Git 外，**每周**把整个工程压缩一份放到另一个盘 | Unity 工程可能损坏 |
| 6 | **记录版本号** | 在仓库根目录放一个 `PROJECT-INFO.txt`，写上 Unity 版本 + 最后更新时间 | 两个人用同一版本 |

> ⚠️ **两个人必须在同一个 Unity 版本上工作**，否则场景文件会互相打不开。

## 二、Unity 项目目录结构（建议直接照建）

```
Assets/
├── Art/
│   ├── Characters/        2D 精灵（角色、NPC、敌人）
│   ├── Environment/       场景贴图、模块化建筑、道具
│   ├── UI/                UI 图、图标、字体
│   └── VFX/               粒子贴图
├── Audio/
│   ├── BGM/
│   └── SFX/
├── Data/                  ★ ScriptableObject 资产（策划改数值不用改代码）
│   ├── Ecology/           生态卡
│   ├── Enemies/           敌人参数
│   ├── Items/             道具与资源
│   └── Islands/           岛屿与翻面状态
├── Prefabs/
│   ├── Characters/
│   ├── Environment/       地标、建筑
│   └── UI/
├── Scenes/
│   ├── Boot/              启动场景
│   ├── Island01/          第一座岛
│   └── Test/              ★ 试验场（随便折腾，不进最终构建）
├── Scripts/
│   ├── Core/              游戏循环、存档、事件总线
│   ├── World/             翻面、平衡度、生态
│   ├── Combat/
│   ├── UI/
│   └── Data/              SO 的类定义
└── Settings/              ★ URP Volume 预设、调色 LUT
```

**三个星号的重点**：
- **`Data/`**：所有数值放这里。改平衡度、改敌人血量**不用改代码、不用重新编译**——这是新手能立刻受益的架构习惯。
- **`Scenes/Test/`**：试验场。所有试错都在这儿做，不要把试验代码写进主场景。
- **`Settings/`**：把 URP Volume 预设存成资产。**"翻面"就是切换两个预设**——这是最省力的实现方式。

## 三、HD-2D 起始参数表（照抄，之后再微调）

| 项 | 起始值 | 备注 |
|---|---|---|
| 相机类型 | **Perspective（透视）** | ⚠️ **不要用正交**，否则退回纯 2D 观感 |
| **相机 FOV** | **30°** | **最重要的一个数**。FOV 小 → 接近等距但保留深度 |
| 相机俯角 | **约 40°**（向下看） | 八方旅人式的斜俯视 |
| 相机距离 | 12–16 单位 | 配合 FOV 一起调 |
| 角色精灵高度 | **64 px** | 不要一上来做 128+ |
| PPU（Pixels Per Unit） | **32** | 64px 精灵＝2 个单位高 |
| **网格尺寸** | **1 单位 = 1 格** | 全项目统一，后期省无数麻烦 |
| 场景贴图 | 128–256 px，**Point filter**，Tiling | **场景贴图也要低分辨率像素感**，否则和像素角色不搭 |
| 色板 | **限制 32–48 色，全项目统一** | 风格统一最便宜的手段 |
| 点光源 | **≤3 个**（前期） | 后处理 + 多实时光源会掉帧 |

> **相机怎么调**：先设 FOV 30、俯角 40、距离 14，然后**只动距离**——距离决定"看多远"，FOV 决定"透视有多强"。这两个调好，画面就有七成对了。

## 四、「高级感」的三根支柱（按性价比排序）

> **如果只做三件事，就做这三件。** 它们能让"方块场景 + 像素小人"立刻看起来像有制作的样子。

| 优先级 | 效果 | 怎么做 | 作用 |
|---|---|---|---|
| **①** | **景深 Depth of Field** | URP Volume → Depth of Field。Focus Distance ≈ 相机到角色的距离；Aperture 5–8 | **最关键**。远景虚化立刻产生电影感，是八方旅人观感的第一来源 |
| **②** | **统一调色 Color Grading** | URP Volume → Color Adjustments / Tonemapping | 全场景统一氛围。成本≈0，效果极大 |
| **③** | **Bloom（泛光）** | URP Volume → Bloom。Intensity 0.3–0.8，Threshold 0.9 | 灯光、魔法、水面发光——夜晚场景的灵魂 |

**第四样（可选但很值）**：**体积光 / 光柱**。
URP 不自带。最便宜的做法是**手工搓**：一个半透明锥体网格 + 渐变贴图，放在光源下方。效果够用，而且完全可控。

> ⚠️ **硬规则**：每个效果**只调 3 个参数，全部不超过 2 小时**，然后**冻结**。后处理调优是 HD-2D 最大的时间黑洞。

## 五、光照：先别碰烘焙

| 阶段 | 做法 |
|---|---|
| **前期（现在）** | **实时方向光 + 2–3 个点光源**。方向光给主光（偏冷），点光源给火把/灯笼（偏暖）。**暖冷对比 = 氛围** |
| 中期 | 场景固定后，再考虑 **Lightmap 烘焙** |
| 永远不要 | 一开始就上烘焙——新手最容易卡住，且场景一改就要重烤 |

**一个小技巧**：让角色**投下阴影**。Sprite 默认不投影，需要一个带 **ShadowCaster** 通道的 Sprite 材质。**角色有影子对"真实感"的提升远超预期**，投入却很小。

## 六、精灵与 3D 的排序（HD-2D 必踩的坑）

**症状**：角色被建筑挡住、或角色穿透墙壁显示在最前面。

**根因**：透明材质默认不写入深度缓冲。

**解法（照做即可）**：

1. **精灵材质用 Alpha Cutout（Alpha Test），不要用 Alpha Blend** —— 深度写入正常，**遮挡问题自动解决**。
2. **相机固定角度**（不旋转）时：把精灵**直接旋转到与相机视平面平行**，**不需要 billboard 脚本**。
3. 只有相机需要旋转时，才加"始终朝向相机"的 billboard 脚本。
4. 精灵导入设置：**Filter Mode = Point**、**Compression = None**、**缩放用整数倍**（否则像素会糊）。

## 八、明确不要碰的东西

| 不要碰 | 为什么 |
|---|---|
| **HDRP** | 为高端画面而生，对你们是灾难性复杂度 |
| **正交相机** | 观感退回纯 2D，HD-2D 的意义就没了 |
| **自己写 Shader / Shader Graph** | 前期一律用 URP 内置 + 后处理 |
| **DOTS / ECS** | 为性能而生，本项目规模用不到 |
| **Timeline 做演出** | 前期用不上，改起来慢 |
| **多人联机** | 复杂度是单机的数倍 |
| **程序化地形生成** | 与手工箱庭抵触，调试困难 |
| **频繁升级 Unity 版本** | 工程打不开的头号原因 |
| **大量 Asset Store 插件** | 插件之间会冲突；只引入解决当前问题的、且你看得懂的 |
