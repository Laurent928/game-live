## 重要度颜色图例

| 标记 | 含义 | 出现时怎么处理 |
|---|---|---|
| 🔴 | **阻塞**：不决定就无法开工 | 优先安排一次讨论 |
| 🟠 | **重要**：影响大、改动代价高 | 尽快决定 |
| 🟡 | **中等**：影响局部 | 可以晚一点 |
| 🟢 | **低**：可延后，或直接采纳建议 | 先搁置 |
| 🔵 | **已定 / 参考信息** | 只需确认 |
| ✅ | **已完成** | 无需动作 |
| ⛔ | **建议不做** | 采纳即可免答 |
| ⚠️ | **风险 / 注意** | 提前留意 |

> 在 **Word 版**（`.docx`）里，以上标记会**自动带底色与文字颜色**，扫一眼就能看出哪几条最急。Markdown 版用 emoji 标记替代颜色。

## 四、白话术语表（给不熟悉游戏开发的人）

> 这一节是为了让**两位都能顺畅审阅**。看不懂正文里的词时回来看这里。

| 术语 | 白话解释 |
|---|---|
| **箱庭** | 一小块精心设计、可以自由走动的关卡区域。比如一座小岛。 |
| **垂直切片** | 从游戏里切出一小段"从头到尾都做完"的样本，用来判断整体值不值得继续做。 |
| **核心循环** | 玩家反复在做的那件事（打怪 → 拿素材 → 变强 → 打更强的怪）。 |
| **占位美术** | 临时用的丑素材（色块、方块）。它的作用是让程序能先跑起来，**不阻塞流程**。 |
| **关键路径** | 一件事必须等另一件事做完才能开始。**关键路径越长，项目越容易被拖死。** |
| **U（成本单位）** | 本文用的工作量尺子：**1 U ＝ 1 座小岛（含 2 个状态）**。约等于 1–2 个"人月"（有经验者）。 |
| **学习期系数** | 新手做同一件事要比有经验的人多花 2–3 倍时间。这不是效率问题，是所有人和所有第一年都这样。 |
| **生态卡** | 把"一片地方长什么样"做成一张可以套用的参数卡（植物、颜色、怪物、资源）。换卡＝换生态。 |
| **S.O.（ScriptableObject）** | Unity 里的一种"数据文件"。好处是：**改数值不用改代码**。 |
| **URP** | Unity 的一种渲染模式。它自带"调色／加雾"的功能，是让"翻面后一眼看出变化"最省力的办法。 |
| **锚定** | 本方案新造的词：一个东西"被世界记住的程度"。记得它的人越多，它越不容易被世界之风侵蚀。 |
| **翻面** | 世界观核心机制：同一座岛在两种状态之间切换（瞬间完成、可预测）。 |
| **世界之风** | 世界观里的"狂暴能量"。它侵蚀存在，是**唯一能造成真正死亡**的东西。 |
| **扭曲** | 被世界之风侵蚀的结果。设定里**只有被扭曲才算真的死**。 |

### 6.2 怎么更新这套文档

1. **回答问题**：直接在 `02` 对应行把 `待答` 改为 `已定`，并写下结论（或另附结论表）。**不要删掉问题本身**——保留它，才知道当初为什么这么定。
2. **两人一起填问卷**：把 `04` 导出的答案回填进 `02`，并在 `02` 附B 标注"已填"。
3. **新增问题**：接着编号往下排（下一个是 **Q58**），并归入某个 Tier。
4. **改变结论**：在 `02` 里写"原定 X → 改为 Y（原因）"，保留变更痕迹。
5. **新增想法**：一律先记入 `02` T3 区，**不在 L0/L1 阶段考虑**；要真正做，必须先按 `03` §12.3 砍掉等价内容。
6. **`01` 原则上不改**：它是"某一时点的审查快照"。世界观升到 V1.2 时，**新写一份 `01b-世界观V1.2-审查报告.md`**，而不是覆盖 `01`。
7. **新增文档要同步进本索引**（`00` §一 文档清单、§5 状态看板）：本目录下 `08` 起的新文档，**一落地就补进清单**，不要等下次整理。索引是给别人指路用的，**它没提过的文档，等于不存在**。
8. **问题单与挂账分家**：`09-世界观待确认问题单` 只管"问什么"，`08-V1.2-修订要点（挂账）` 只管"V1.2 要改什么、改到哪了"。**回答完先回填 `08`，问题单不承载结论**。

## 七、三个最该记住的结论

1. **世界观不实现成内容量，实现成规则。** 世界观里最珍贵的东西（能量总纲、翻面、死亡非真死）全部是规则，而规则便宜、素材昂贵。
2. **先写"不做清单"，再写"要做清单"。** `03` §12 的 12 项不做 + `03` §12.2 的新手专项不做，能省下 24–38 U——这就是"做得完"的全部来源。
3. **能做完的第一章，胜过做不完的史诗。** 在现有的时间条件下，**"完整 RPG"需要 15–20 年**。但"做小一点"不是答案——**把"发布"提前才是**（`05`）：先上线一个 60–120 分钟的**序章**（约 1–1.5 年），之后每 3–6 个月更新一块。设定**一个字不删**，它们就是后续更新的内容池。
