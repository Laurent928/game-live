# 07 · HD-2D（类八方旅人）实践路线

> **这份文档解决一件事**：你们决定做"类八方旅人"风格，而你是零基础——**到底怎么一步步做出来**。
> **对应问题**：`02` **Q11e（游戏视角与美术风格）—— 本文件即为该题的答案**，`02` 该行已更新为「HD-2D」。
> **相关**：`05-分章节发布方案.md`（路线）、`03` §8（Unity 与零基础技术建议）。

## 1. 先纠正一句话，再确认这个选择是对的

### 1.1 需要纠正的：难度并不对称

"不会比 2D 难上太多"这句话，**对美术成立，对程序不成立**：

| 方面 | 相对纯 2D 的成本 | 说明 |
|---|---|---|
| **美术** | **+10–20%**（几乎一样） | 角色还是**画 2D 像素精灵**——和纯 2D 的工作量没区别。多出来的只是场景贴图与模块化建筑 |
| **程序** | **+30–60%** | 3D 场景搭建、相机、后处理、光照、精灵与 3D 的遮挡排序、性能 |
| **总计** | **约 +25–40%** | 序章从 800–1400h 变成 **约 1000–1900h**，时间从 1–1.5 年变成 **约 1.2–2 年** |

**所以要诚实地把时间线放宽一点。** 但下面才是重点。

### 1.2 为什么这个选择仍然是对的（而且理由比"不会难太多"更强）

> **HD-2D 的本质是：2D 精灵 + 3D 场景 + 后处理。**
> 也就是说——**画的东西没变，卖相提升了一个档次。**

这一点直接命中她的顾虑：

- 她说"**纯 2D 太掉价**"——这个直觉是对的。而 HD-2D 恰好让"像素小人"变成一种**被主流认可的高级风格**：《八方旅人》本身就是商业大作。**这不是妥协，是选了更聪明的表达方式。**
- 她的美术工作量**几乎不变**，但画面从"平面手绘"变成"有景深、有光照、有氛围的立体世界"。

**结论**：这个决定我支持，而且它会显著提高你们"做给别人看"的说服力——**这正是她最在意的那件事**。

## 2. HD-2D 的技术配方（可直接照抄）

> 这一节是整份文档最实用的部分。**照这个配，第一周就能看到"那个感觉"。**

### 2.1 引擎与管线（必须）

| 项 | 选择 | 为什么 |
|---|---|---|
| 引擎 | **Unity（LTS 版，整个项目不升级）** | 与 `03` §8 一致 |
| 渲染管线 | **URP**（不是 Built-in，也不是 HDRP） | **HD-2D 的"高级感"完全来自 URP 的 Volume 后处理**，这是硬性前提 |
| 相机 | **透视相机（Perspective）**，不是正交 | 这是"3D 感"的来源。用正交就退回纯 2D 观感了 |
| 角色 | **Sprite Renderer**（2D 精灵） | 美术成本低的关键 |
| 场景 | **3D 网格**（ProBuilder 或模块化模型） | 提供空间感与光照承载 |

### 2.2 起始参数表（照抄，之后再微调）

| 项 | 起始值 | 备注 |
|---|---|---|
| 相机类型 | **Perspective** | 关键 |
| **相机 FOV** | **30°** | **最重要的一个数**。FOV 小 → 透视畸变低、接近等距，但保留深度 |
| 相机俯角 | **约 40°**（向下看） | 八方旅人式的斜俯视 |
| 相机距离 | 12–16 单位 | 配合 FOV 一起调 |
| 角色精灵高度 | **64 px** | 不要一上来做 128+ |
| PPU（Pixels Per Unit） | **32** | 64px 的精灵＝2 个单位高 |
| **网格尺寸** | **1 单位 = 1 格** | 全项目统一，后期省无数麻烦 |
| 场景贴图 | 128–256 px，**Point filter**，Tiling | **贴图也要是低分辨率像素感**——否则高清场景 + 像素角色会不搭 |
| 色板 | **限制 32–48 色，全项目统一** | 风格统一最便宜的手段 |
| 点光源 | **≤3 个**（前期） | 后处理 + 多实时光源会掉帧 |

### 2.3 「高级感」的三根支柱（按性价比排序）

> **如果只做三件事，就做这三件。** 它们能让"方块小人 + 简陋场景"立刻看起来像有制作的样子。

| 优先级 | 效果 | Unity 里怎么做 | 作用 |
|---|---|---|---|
| **① ** | **景深 Depth of Field** | URP Volume → Depth of Field。Focus Distance ≈ 相机到角色的距离；Aperture 5–8 | **最关键的一个**。远景虚化立刻产生"电影感"，是八方旅人观感的第一来源 |
| **②** | **统一调色 Color Grading** | URP Volume → Color Adjustments / Tonemapping | 全场景统一氛围。成本≈0，效果极大 |
| **③** | **Bloom（泛光）** | URP Volume → Bloom。Intensity 0.3–0.8，Threshold 0.9 | 灯光、魔法、水面发光——夜晚场景的灵魂 |

**第四样（可选但很值）**：**体积光 / 光柱**。
URP 不自带，两个办法：① 用免费的体积光资源包；② **手工搓**——一个半透明锥体网格 + 渐变贴图，放在光源下方。第②种最便宜、效果也够用，而且完全可控。

### 2.4 光照：先别碰烘焙

| 阶段 | 做法 |
|---|---|
| **前期（推荐）** | **实时方向光 + 2–3 个点光源**。方向光给主光，点光源给火把/灯笼/魔法（暖色），环境光给冷色补光。**暖冷对比 = 氛围** |
| 中期 | 场景固定后，再考虑 **Lightmap 烘焙**（省性能、更细腻） |
| 永远不要 | 一开始就上烘焙——它是新手最容易卡住的地方，而且场景一改就要重烤 |

**一个小技巧**：让角色**投下阴影**。Sprite 默认不投影，需要一个带 ShadowCaster 通道的 Sprite 材质。**角色有影子这件事对"真实感"的提升远超预期**，投入却很小。

### 2.5 精灵与 3D 的排序问题（HD-2D 必踩的坑）

**症状**：角色被建筑挡住、或者角色穿透墙壁显示在最前面。

**根因**：透明材质默认不写入深度缓冲。

**解法（照做即可）**：
1. **精灵材质用 Alpha Cutout（Alpha Test），不要用 Alpha Blend** —— 这样深度写入正常，**遮挡问题自动解决**。
2. 相机**固定角度**（不旋转）时：把精灵**直接旋转到与相机视平面平行**，**不需要 billboard 脚本**——最省事。
3. 只有当相机需要旋转时，才加一个"始终朝向相机"的 billboard 脚本。
4. 精灵导入设置：**Filter Mode = Point**、**Compression = None**、**缩放用整数倍**（否则像素会糊）。

### 2.6 明确不要碰的东西（HD-2D 版）

| 不要碰 | 为什么 |
|---|---|
| **HDRP** | 为高端画面而生，对你们是灾难性的复杂度 |
| **路径追踪 / 光线追踪** | 完全不需要 |
| **自己写 Shader** | 前期一律用 URP 内置 + 后处理 |
| **后处理调优成瘾** | **最大的时间黑洞**。规则：每个效果只调 3 个参数，全部不超过 2 小时，然后**冻结** |
| **高分辨率写实场景贴图** | 会破坏像素风格的统一，还更贵 |

## 3. 零基础实践路线（五个阶段，每步都有可见产出）

> **排序原则**：把这个项目**最大的不确定性放在最前面验证**。
> 你们最大的不确定性不是"能不能写代码"，而是——**"我们到底能不能做出那个感觉"。** 所以第 1 阶段就是去验证它。

### 阶段 0 · Unity + C# 基础（2–3 周）

- **做什么**：跟完一个官方 2D 或 3D 小游戏教程，**做到能打包运行**
- **产出**：一个能跑起来的小游戏（内容与你们的项目无关）
- **通过标准**：能独立打包 / 看懂教程里 80% 的代码 / 改一个数值能看到游戏变化
- ⚠️ **不要跳过这一步。** 零基础同时面对"学工具"和"做设计"两个未知，几乎必然卡死

### 阶段 1 · 🎯 做出「一张截图」（2–3 周）— **最重要的一步**

**这一阶段不写任何游戏逻辑，只做画面。**

- **做什么**：
  1. ProBuilder 搭一小块空地 + 2–3 个建筑盒子 + 一棵树（**全部用低分辨率像素贴图**）
  2. 放一个精灵角色（先用免费素材或 AI 生成的占位图）
  3. 相机：**Perspective、FOV 30°、俯角 40°、距离 14**
  4. URP Volume：加 **景深 + 调色 + Bloom**
  5. 光照：一个方向光（冷）+ 两个点光源（暖），角色开阴影
  6. 加一点点粒子（漂浮的光尘）
- **产出**：**一张截图。这张截图就是你们的美术方向定稿。**
- **为什么值得放在这么前**：
  - 它是这个项目**唯一的高风险未知**，越早验证越好；
  - 它是**给卿宝看的第一件东西**——"看，我们的游戏长这样"。这一件事对信心的作用，超过十份文档；
  - 它同时确定了美术规格（精灵多大、色板多少、光照风格），后面所有人都照着它做。
- **通过标准**：把截图给不知情的人看，对方会说"这个看起来像八方旅人那种"。

### 阶段 2 · 让角色动起来（3–4 周）

- 角色移动 + 碰撞 + 相机跟随（**Cinemachine**）
- 4 方向（或 8 方向）行走动画——**先用免费素材**，不要现在就让卿宝画全套
- **产出**：一个能在场景里走动的小世界
- **顺带学会**：输入系统、Cinemachine、动画状态机

### 阶段 3 · 加入「翻面」（对应 `03` §5 的 **L0**）

- 按键触发：换场景贴图/材质、换 Volume 预设（调色）、显隐地标、开关点光源
- **产出**：按一个键，**同一个 HD-2D 场景"翻面"**
- **通过标准**：录一段 15 秒视频，别人能看出"世界变了"
- **这一步的额外意义**：HD-2D 的"翻面"会非常好表现——**换调色 + 换光照 + 换雾**，观感差异极大，而成本几乎为零

### 阶段 4 及之后 · 回到 `03` §5 的 L1–L3

之后按 `03` 的 L1（规则闭环）→ L2（微切片）→ L3（序章）继续，技术路线固定为 HD-2D。

## 5. 坑清单（按踩到的概率排序）

| # | 坑 | 后果 | 对策 |
|---|---|---|---|
| 1 | **后处理调优成瘾** | 数周时间消失，画面只好了 5% | 硬规则：每效果 ≤3 个参数、总共 ≤2 小时，然后冻结 |
| 2 | **精灵被建筑挡住 / 穿透** | 看起来像 bug | 精灵材质用 **Alpha Cutout**；相机固定角度则直接旋转精灵对齐 |
| 3 | **一开始就上光照烘焙** | 卡住数天，且场景一改就重烤 | 先用实时光照；场景定型后再考虑 |
| 4 | **场景用高清贴图** | 和像素角色不搭，风格撕裂 | 场景贴图也是 **128–256px + Point filter** |
| 5 | **精灵被非整数缩放** | 像素糊掉，"像素风"变成"模糊风" | 缩放用整数倍；导入设 Point + 不压缩 |
| 6 | **点光源开太多** | 掉帧，且后处理叠加 | 前期 ≤3 个 |
| 7 | **正交相机** | 观感退回纯 2D，HD-2D 的意义没了 | 必须 **Perspective** |
| 8 | **HDRP / 自写 Shader** | 复杂度爆炸 | 一律不碰 |
| 9 | **把场景做太大** | 第一张图就失去控制 | 阶段 1 只做**一小块空地**，能出效果就够 |
