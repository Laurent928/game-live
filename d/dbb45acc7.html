1. 前置条件，以及它对计划的三个硬约束

这一节是全部产能测算的输入。以下是规划用的工作假设，不是对任何一方的评价；两位看过之后都可以改。

项规划假设
团队2 人，创作与实现并行推进
有效投入每周合计约 10–14 小时（非全职；两人都还有学业与生活，投入会有波动）
引擎Unity
基础两位都是初次接触游戏制作，处在学习阶段
项目目标以学习为主；产出目标定为"能做完，并让别人玩到"

三个硬约束（后面所有安排都服从它们）

#硬约束直接后果
🔴 约束一有效开发力量有限全部计划的产能基数是 10–14 小时/周 ≈ 500–700 小时/年。所有范围决策以此换算。
🔴 约束二任一方的时间投入都不应成为前提任何一块产出都不能落在关键路径上。缺了美术，游戏也必须能完整跑通（§9 规则一）。
🟠 约束三目标是学习，不是交付评价标准从"什么时候做完"改为"每 2–3 个月有没有一个能玩/能给人看的东西"。相应地，允许项目永远不到终点——只要每一站都有收获（§5）。

一个重要且令人宽慰的推论：既然目标是学习，那么这套世界观不需要被完整实现。它作为"题材与动机"已经完成任务了——真正要学的是做游戏；而做游戏需要的题材，一座岛就够了。

2. 现实体检：把数字重算一遍

这一节可能会让人不太舒服，但它比任何设计建议都重要。先看清速度，再谈做什么。

2.1 单位换算

项口径
1 U＝ 1 座岛屿箱庭（含 2 个状态、骨架复用）
1 U 的工时（有经验者）≈ 160–320 小时（1–2 人月）
学习期系数×2–3（第一次做游戏，做同样的事约为有经验者的 2–3 倍耗时）
1 U 的工时（本项目）≈ 320–960 小时
每周有效产能10–14 小时（两人合计）
每年产能≈ 500–700 小时

2.2 🔴 换算结果（这就是全部真相）

目标原估算本项目实际需要按 12h/周折算
原 P0 规则原型（0.3–0.5 U）48–160h100–480h2–9 个月
原 P1 垂直切片（5.4 U）864–1728h1700–5200h3–8 年

结论：

  • 🔴 原 P2（3–5 小时短篇）必须放弃。它不是"难"，而是"不可能在现有时间尺度内完成"。
  • 🔴 原 P1（5.4 U）也要放弃。3–8 年的单一目标会在第 6 个月就压垮动力。
  • 🔴 必须把目标下调到"微型成品"：一个 30–60 分钟、有开头和结局、能发给朋友玩的小游戏。

2.3 但这里有一个好消息

学习期系数 ×2–3 的"额外成本"不是浪费——它就是学费，而且学费换来的是技能，技能可以复用到第二款、第三款游戏。

  • 第一款游戏：花 2 年做一个 60 分钟的游戏（很慢，但你会变成一个会做游戏的人）
  • 第二款游戏：花 6 个月做一个 2 小时的游戏
  • 第三款游戏：这才是你们真正想做的那个游戏

所以本方案的核心建议是：第一款游戏的目标不是"实现这个世界观"，而是"把两位变成能做这个世界观的人"。 世界观里那些最贵的部分（旧主城、空岛、海底、4 职业、船战），留给第三款游戏。

3. 三条铁律

#铁律为什么
🔴 铁律一先写"不做清单"，再写"要做清单"第一失败模式不是做错，而是同时想做太多。不做清单是最便宜的产能。
🟠 铁律二新系统必须先砍掉一个旧系统硬性预算制。防止"每讨论一次就多一个系统"。
🔴 铁律三阶段验收不通过，不进入下一阶段第二失败模式是"每样都做了一半"。做完一个小的，胜过做一半一个大的。

🔴 给零基础团队的补充铁律（铁律零）：在开始做自己的游戏之前，先完整复刻一个别人的小游戏教程。 不要跳过第 0 步（§5）。零基础同时面对"学工具"和"做设计"两个未知，几乎必然卡死；先跟完一个完整小游戏，就拿到了工作流、C# 基础和打包流程。

6. 八个机制提案 M1–M8

挑选标准：每一条都从已有设定推导（不新增概念）、都能被零基础团队实现、都直接回应某一个结构性问题。 实现难度：★ = 新手在 L1 就能做；★★ = L2 阶段；★★★ = L3 之后。

🟠 M1 · 能量同轴：魔法值＝岛屿平衡度 ★★

回应：Q6 存疑项（巫师施法用什么能量）+ 主题落地施法抽取的是本地能量。建议只对大型行为生效（符文/仪式/催化翻面），普通战斗的抽取量设为可忽略。于是：

  • 解答了 V1.1 未明说的后果——人类的生存手段本身在加速灾难；
  • 让"人祸"主线在机制上成立，不需要额外系统；
  • 道德对立只出现在关键抉择处，不打搅战斗爽快感。

实现：一个 float 变量 + 一个 UI 条 + 几条规则。这是本方案里投入产出比最高的机制。

🟠 M2 · 海图即锚定：探索＝给世界续命 ★★

回应：R4（世界之风为何聚集）+ R6（幽灵岛）+ 缺口7（航线原理）绘制海图、记录航线、命名岛屿 → 提升该岛的锚定 → 抵抗世界之风与消散。

  • 把最普通的"地图开雾"升级为"对抗遗忘"，成本近乎为零；
  • 把"航海日志"变成叙事载体（Q53）；
  • 给玩家一个非战斗、可累积、主题纯粹的目标。

实现：一张图 + 一个已访问列表 + 一段文本。L3 再做。

🟠 M3 · 翻面窗口：一个事件，多种玩法 ★★

回应：V1.0 风险1（翻面别变成换地图）+ 风险9（逼玩家刷岛）把翻面做成可视化时间轴事件，窗口内提供多种解法：

解法动机玩家动作
撤离善救出居民（难度在时间与载量）
抢收贪搬空独有资源（风险与收益并存）
稳定智用符文/术士延缓（消耗稀有资源与人力）
催化恶加速翻面以强制获得想要的生态状态

L2 只做 2 种（建议：撤离 + 催化，因为这两者构成最强的道德对立）。

🟠 M4 · 催化翻面：让玩家可以选择成为灾难 ★★

回应：把世界观最强的道德张力变成玩家动词玩家可以投入能量/资源推动某座岛翻面，以获取特定状态的资源。这是"疏导"的镜像。

  • 玩家会自己发现："我为了拿材料，让一座岛的人失去了家。"
  • 配套建议：催化后该岛留下长期后果（居民变船民 / 憎恶增多 / 世界之风聚集），让玩家的贪婪在世界上留下可见疤痕——改一个参数 + 一句日志，这是最便宜的"选择后果"实现方式。

🟠 M5 · 死亡 → 灵魂窗口：把死亡从读档变成事件 ★

回应：R9（最大设计债务）按 Q17 的损失阶梯实现。核心是：灵魂无人收集就会流失。

  • L1 阶段就能做最简版：死亡 → 掉落资源 + 一句"记忆缺口"文本 → 在最近的庇护点复活；
  • L2 加入"承载者"概念；
  • 被世界之风侵蚀而死 → 永久死亡（世界里唯一真正的死）。

成本：改动极小，收益极大。这是本方案性价比最高的一条。

🟡 M6 · 船即角色：命名、里程与幽灵船 ★★★

回应：V1.0 风险7（船改造与世界规则脱节）第十一条说船需巫师附魔制造——意味着船是人工创造的存在，因此它也有锚定。

  • 命名、累积航行里程 → 船的锚定上升 → 解锁能力；
  • 长期无人维护 → 幽灵船（＝船的扭曲/消散态）。
  • L3 只做最简版：给船命名 + 1 个"航行里程"数值 + 1 个解锁。

🟡 M7 · 深度即进度：下潜＝接近另一面 ★★★

回应：R1 图层模型 + 第十四/十六/十七条若 Q14 选 A（图层叠置），则海底区域就是"里层"地形，船只改造＝下潜能力＝进入更深、更接近另一面的能力。注意：这一条对应"自由潜行"，已列入不做清单。L3 之后再考虑，且只做"下潜点"（按一个键进入一个小场景），不做自由三维移动。

🟡 M8 · 三仪表：把"以小见大"做成 UI ★★

回应：V1.0 风险2（规则过抽象，且 V1.1 恶化了）

仪表尺度对应设定何时做
岛屿平衡度世界翻面进度、维持与催化L1
自身失衡值个人漩涡、扭曲风险L1
船的锚定值媒介船的成长与幽灵船风险L3

玩家不需要读设定集，看着表就能理解世界观；当它们同时升降时，玩家会自己悟出"这个世界的规则是同一套"——用机制而不是文本，说出第二十六条想说的话。L1 从 2 个仪表开始（平衡度 + 自身），第三个留到 L3。

7. 主线与结局的融合方案（回应附录B1）

第二十七条把"解放固有命运/反抗群星"与"人祸"并列待定。它们其实是同一个答案的两半：

人类为了活下去，固定了不该被固定的东西。稳定符文把能量固定在岛屿上（第十条）；星象被固定，命运因此凝固（第二十七条）。这是同一个动作在不同尺度上的重复——都是"把流动的东西钉住"。而世界之风的成因恰恰是"能量该流动而受阻、周期性凝固、积累过多即爆炸"（第十九条）。所以：符文救下的每一座岛，都在为世界之风添一份燃料。旧主城的符文防线长期阻挡能量，最终被一波爆发冲入海中——它不是死于意外，它是死于自己活了太久。

这个方案一次性收口五件事：

  1. 附录B1 的"二选一" → 合并为单一主线（Q55）；
  2. "人祸"的具体施害者 → 稳定特许体系，以及所有依赖它的人——包括玩家自己；
  3. 旧主城之灾的必然性 → 不是天灾，是"稳定"的账单；
  4. 世界之风为何必然存在 → 它是被固定能量的出口，不是外来的邪恶；
  5. 主角身份的正确性 → 航海士＝不固定的人＝流动的化身。

终局抉择（两个都不是"好结局"）：

结局世界人类
继续固定活下来，但永远不健康（扭曲与憎恶成为常态成本）定居文明延续，术士世代接力
解放命运能量重新流动，世界之风失去成因、扭曲减少定居文明的根基崩解，人类退回海上

L2 的极简实现：结局不用做大场面。两个按钮 + 两段文字 + 一张不同的远景图就足够。情感落点可以靠 M2：玩家一路画下的海图，在"解放命运"结局里被自己抹掉。

8. Unity 与零基础技术建议

这一节是为 Unity + 零基础这个组合写的。

8.1 版本与项目设置（避开经典坑）

项建议理由
Unity 版本选一个 LTS（长期支持）版，然后在整个项目周期内不升级升级 Unity 是学生项目最常见的"工程突然打不开"原因
渲染管线URP（2D 或 3D 都行）URP 的 Volume 后处理（色调/雾/曝光）是"翻面一眼可见"的最便宜手段
视角见 §8.2（04 问卷第 1 题）决定全部美术工作量
版本管理GitHub Desktop（图形界面）+ 每天结束前提交一次零基础不要用命令行 Git；但一定要用，否则丢工程是必然事件
备份除 Git 外，每周把整个工程压缩一份放另一个盘/云盘Unity 工程可能损坏
教程官方 Unity Learn 入门路径 + 跟着做完 1 个完整的 2D 或 3D 小游戏第 0 步（§5）就是这个

8.2 视角选择：对新手最重要的一次取舍

方案难度（阿丞）难度（卿宝）适合
A · 2D 俯视（像素或手绘）最低（Sprite + Tilemap，教程最多）中（要画俯视素材，但每件都很小）零基础首选
B · 2.5D 等距（斜 45°）中最高（等距素材最难画，且方向多）不推荐
C · 3D 低多边形中（免费低模资源丰富）低（场景用免费资源，美术侧只做立绘/UI/图标）想保留"海洋感"时的首选
D · 3D 写实 / 第一人称高极高不做（§12.1 第 12 条）

建议：A 或 C（04 问卷第 1 题，两位可以一起定）。如果想保留世界观里"大海与岛屿"的体量感，选 C（低多边形 3D），并把场景资产全部交给免费资源库，美术侧只负责立绘、UI 风格、图标、插画。

8.3 数据驱动：用 ScriptableObject 落地"生态卡"

§10.2 的"生态卡"在 Unity 里有天然对应物：ScriptableObject（SO）。

  • 每种生态 = 一个 SO 资产，字段就是 §10.2 的那张参数表；
  • 翻面 = 换一个 SO 引用 + 换光照/Volume 权重 + 显隐地标对象；
  • 好处：改数值不需要改代码，也不需要重新编译——这正好契合"按所有权分工"的安排（§9 规则二）；
  • 这是新人能掌握、且立刻受益的架构模式，建议在 L1 就学。

8.4 明确不要碰的东西（新手陷阱）

不要碰为什么
Shader Graph / 自写 Shader学习曲线陡，且本项目不需要
DOTS / ECS为性能而生，本项目规模用不到，会浪费数周
Timeline 做演出前期用不上，且改起来慢
多人联机 / Netcode复杂度是单机的数倍（已列不做清单）
程序化地形生成与"手工箱庭"抵触，且调试困难
自研工具链 / 自研框架不是来做引擎的
随便引入大量 Asset Store 插件插件之间会冲突；只引入解决当前问题的、且能看懂的

8.5 可以放心学的东西

ScriptableObject · Cinemachine（相机会自动变好看）· Tilemap（2D）或 ProBuilder（3D 快速搭场景）· 新输入系统 · 免费资源站（Kenney / OpenGameArt / 免费音效库）· Application.persistentDataPath + JSON 存档。

9. 协作规则

这一节只解决一件事：让项目在任何一方时间紧张的时候，都还能继续往前走。提前说明：以下不是对任何人的评价，而是两人合作做游戏的工程安排，对双方都成立。

规则一 · 任何一块产出都不能落在关键路径上（最重要的一条）

缺了美术、缺了音乐、缺了文案，游戏也必须能完整跑通。

  • 所有占位都用 Unity 自带的 Cube / Capsule / 纯色 Sprite；
  • 永不出现"等某一块素材才能继续"的状态；
  • 任何一方的产出都是替换，不是前置。这既是工程纪律，也让人不必因为"还没做"而产生压力。

规则二 · 按"所有权"分工，而不是按"任务"分工

两个人擅长和喜欢的部分不同，所以按所有权划分——各自负责的领域自己说了算，对方不插手。（阿丞＝实现向；卿宝＝创作向；两者交叉的算共同。）

🎨 卿宝 拥有（创作向）⚙ 阿丞 拥有（实现向）
世界观与设定的取舍 · 角色是谁、长什么样 · 文案与对白 · 音乐与氛围 · 美术风格与 UI系统与玩法实现 · 数值与平衡 · 关卡搭建 · 程序架构 · 排期与推进

具体做法：需要卿宝拿主意的事，做成选择题而不是问答题（这就是 04-互动问卷.html 的作用）——每次不超过 30 分钟，而且随时可以只答一半。

规则三 · 力气花在玩家最感觉得到的地方

美术与音乐的成本，和它带来的感受不成正比。真正被记住的往往是数量最少的那几件。

性价比高（优先做）性价比低（尽量不做）
1–2 张角色立绘大量场景素材（用免费资源）
UI 风格 + 图标（一套就够）每个道具一个图标
1–2 首主题曲每个场景一首 BGM（复用 + 免费库）
一段关键文案（开场／结局）全部对白（L2 阶段对白量极小）
一个 Logo / 标题画面宣传片、动效

规则四 · 两人节奏不一致时怎么办

两人的可用时间本来就会波动（考试、忙闲、状态），节奏不一致是常态，不是问题。四条建议：

  1. 计划按"最低投入"来排——任何一方都不欠账。这样多做的每一件都是惊喜，而不是欠账；反过来按"最好的情况"排，计划必然落空。
  2. 每 1–2 周一次 30 分钟的"一起看进度"：把最新的可玩版本跑给对方看，而不是汇报进度。让人玩到做出来的东西，是维持动力最有效的方式（对双方都是）。
  3. 用邀请代替催促："这个我拿不准，你帮我选一个" 远比 "那个做完了吗" 有效。参与感来自被需要，而不是被检查。
  4. 允许长时间停摆（见规则五）——项目不会因为停了两个月就报废。

规则五 · 把它当共同爱好，而不是作业

  • 不设交付日期，不设"这个月必须做完什么"；
  • 忙的时候可以完全停下，工程会留在 Git 上，随时可以回来；
  • 明确允许"停在这里也挺好"——第 0 步或 L0 完成，本身就是一件值得骄傲的事。

一句话：这个世界的两位作者，同时也是这个项目的两位开发者——这本身就是很少见的好条件。别让它变成压力来源。

10. 内容生产管线（省成本的关键）

10.1 岛屿 ＝ 骨架 + 生态卡 + 地标槽 + 恒定物

岛屿
├── 骨架（高度图 + 碰撞 + 港口位置）        ← 手作一次，两面共用
├── 生态卡（ScriptableObject，见 10.2）     ← 数据驱动，可组合
├── 地标槽 × 2–3（每个状态填不同地标）      ← 预制体库复用
└── 恒定物 × 1（断桅、刻字岩壁、灯塔基座）  ← 跨两面不变

恒定物是这套管线里最重要的一个设计：它是玩家"这是同一座岛"的感知锚点，成本近乎为零，但能让"骨架复用"不被察觉为偷工。

10.2 生态卡（ScriptableObject）字段建议

字段例
地表材质 ID草地 / 沙 / 火山岩 / 珊瑚
植被组 ID阔叶 / 芦苇 / 仙人掌 / 无
后处理预设（Volume）冷/暖、雾浓度、曝光——"一眼看出世界变了"的最便宜手段
敌人表复用已有敌人，换组合与数值
资源表决定"某些资源只在特定状态出现"（第八条）
天气集合晴 / 雨 / 风暴
水面参数颜色、浪高、能见度
环境音 ID复用音频库

10.3 组合矩阵（不做手工岛屿的理由）

第七条：「同一种生态也可能因为翻面时的自然能量状态不同而产生不同的转换分支，例如森林可能转变为湿地或沙漠。」

这句话本身就是程序化组合的说明书。把它实现为数据表：

基础生态平稳 →失衡 →失控 →
密林密林湿地沙漠
湿地湿地密林沙漠
火山火山灰烬地珊瑚（水下翻起）
珊瑚珊瑚湿地冰原
沙漠沙漠火山灰烬地
冰原冰原沙漠湿地

6 种基础生态 × 3 级状态＝ 一套可覆盖大量岛屿的矩阵，而美术量只需要 6 套生态资产。这是本方案里最大的单点节省。但 L2 只需要 2 个生态卡（例如"密林"与"沙漠"）。不要一开始就做 6 个。

10.4 🔴 翻面的具体实现（0.3–0.5 U 而非 2.5–3.5 U）

背景：第七条要求"翻面后的岛屿会进入全新的生态与地图，而不是简单改变原地图的外观"——这一句与实际可完成性直接冲突（01 §5.2），需与设定者协商降级。

一次翻面 = 以下五步的原子操作：

  1. 换生态卡（SO 引用替换）；
  2. 换敌人表 / 资源表；
  3. 换后处理与光照（"一眼看出变了"的最便宜手段）；
  4. 替换 2–3 个地标预制体（显隐 / 换模型）；
  5. 保留恒定物。

在 Unity 里这五步基本是"换引用 + SetActive + 调 Volume 权重"，代码量很小。

纪律：先做这个便宜版本，用试玩反馈决定要不要加投入。不要在没有试玩数据之前，就为"全新地图"买单。

11. 成本口径与成本锚点

11.1 相对单位 U

1.0 U ＝ 1 座手工岛屿箱庭（含 2 个状态、骨架复用） 1 U ≈ 160–320 小时（有经验者）· 学习期系数 ×2–3（见 §2.1）

为什么用相对单位：绝对人月估算在非全职、零基础的团队里必然失真。相对单位能让你在"做 A 还是做 B"时做出正确取舍，而不会给出假精确的日期。
