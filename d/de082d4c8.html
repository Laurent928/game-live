05 · 常见问题与卡点

卡住的时候来这里查。按"出现的概率"排序。

一、环境类

Q：Unity Hub 下载特别慢 / 下载失败换时间段（凌晨通常快），或者换一个镜像源。不要因为下载慢就换引擎——这会把前面所有进度清零。

Q：不确定该装哪个版本装列表里最上面的 LTS。不要选标着 Beta / Preview / Tech Stream 的。

Q：场景打不开 / 报版本不一致八成是两个人用了不同的 Unity 版本。约定一个版本写进 PROJECT-INFO.txt，两个人都用同一个。工程周期内不升级。

Q：工程突然损坏 / 打不开这就是为什么：

  1. 每天 Push（Git 就是你的后悔药）；
  2. 每周额外压缩一份备份放到另一个盘。

坏了就回退到最近一次提交。

Q：Git 仓库变得特别大 / 推不动检查 .gitignore 是不是漏了 Library/。这个是必须忽略的（Unity 的缓存，动辄几个 GB）。已经提交过的话，需要把 Library/ 从历史里移除。

Q：Git 冲突了，看不懂 不要自己硬解。 冲突通常发生在场景文件（二进制，无法合并）。做法：

  1. 两个人约定不同时改同一个场景；
  2. 真冲突了 → 保留一份能打开的，另一份从提交历史里取需要的东西；
  3. 找社团的人帮你看一次，看一次就会了。

二、画面类（HD-2D 特有）

Q：画面很平，一点都不像八方旅人按这个顺序查：

  1. 相机是不是 Perspective？（用了正交就全完了）
  2. FOV 是不是 30 左右？（FOV 太大就没有"贴近平面的等距感"）
  3. 有没有加景深 Depth of Field？这一项贡献了一半的效果
  4. 有没有统一调色？
  5. 场景贴图是不是也低分辨率？高清场景 + 像素小人 = 风格撕裂

Q：像素糊了，不像像素风

  • 精灵导入：Filter Mode = Point、Compression = None
  • 缩放用整数倍（比如 2×、3×，不要 1.7×）

Q：角色被建筑挡住 / 角色穿透墙显示在最前面精灵材质改成 Alpha Cutout（Alpha Test），不要用 Alpha Blend。深度写入正常后遮挡就对了。（见 02-技术与环境搭建.md §6）

Q：后处理调了好久还是不满意停。硬规则：每个效果只调 3 个参数、总共不超过 2 小时，然后冻结。第一版的目标是"有那个感觉"，不是"完美"。调优是这个项目最大的时间黑洞。

Q：掉帧

  • 实时点光源减到 3 个以内
  • 关掉暂时不用的后处理效果
  • 先别管性能，等能跑了再优化

Q：光照很假 / 建筑没有影子先用实时方向光 + 点光源。想让角色投阴影，需要一个带 ShadowCaster 通道的 Sprite 材质。烘焙（Lightmap）先不要碰——场景一改就要重烤，新手会卡在这里好几天。

三、做法类

Q：不知道下一步做什么看 01-路线图与里程碑.md 的里程碑看板，找第一个没打勾的。只做那一个。

Q：想加一个新玩法 / 新系统 先砍掉一个等价的旧系统（铁律二）。如果砍不掉，说明现在不该加。

Q：范围越做越大，序章迟迟做不完回 01 §3 看那 9 项内容清单。9 项之外的一切都不做，写进"后续"列表里。

Q：某个设定必须定了才能写代码只需要定那一条，不要顺手把整个世界观重新过一遍。定完立刻回去写代码。

Q：我在"研究怎么做"上花了太多时间一个自检：这周我改的东西，能不能让画面/游戏多动一下？ 不能的话，那大概率是拖延。

四、协作类

Q：两个人都忙，进度停了很久正常。看 03 §7：停两个月不叫失败。 唯一要做的是停之前把状态写进 PROGRESS.md。

Q：我一个人在做，感觉像独自扛这是真实的感受，也是最容易被低估的成本。三个建议：

  1. 社团那条路要真的走——你在那边也能获得"被认可"和"进度感"，不必把全部的自我价值都押在这一个项目上；
  2. 把"每周 2 小时并肩时段"当成硬日程，不是可选项；
  3. 不要记账（"我做了多少小时她做了多少"）。这笔账永远算不平，而且本来也不该按小时算。

Q：想催，但不能催不要催。改成做三件事：

  1. 把任务池建起来（03 §3）——她有空自己拿一张，你不需要开口；
  2. 每周并肩时段只展示、不问进度：跑一遍最新版本，说"这周游戏变了什么"；
  3. 她交了东西就立刻进游戏，并告诉她"进游戏了"。

（正反馈的最短回路，比任何催促都有效）

Q：她做的东西一直没进游戏那她很快就会停止产出。她给的东西当周就必须进游戏——哪怕是当占位图放进去。

五、心态类

Q：感觉做不完了看 01 的里程碑看板，只看第一个没打勾的。项目是按"每 3–6 个月可见进展"设计的，不是按"两年后一次交付"设计的。

Q：做出来的东西很丑，很受打击阶段 1 的目标就是"丑但有那个感觉"。HD-2D 的优势恰恰是：丑的素材在正确的相机、光照和后处理下，也能看起来像样。

Q：没动力了回到最小的那个动作：打开 Unity，让它跑起来，改一个数值，看看变化。 五分钟就够。动力通常是从"动了"里长出来的，不是等来的。

Q：这个游戏到底有没有意义这是一个可以问的问题，但它不该由进度来回答。项目做完了、没做完、做得好、做得烂——都不改变做它的人是谁。

六、求助优先级

顺序渠道适合什么问题
1社团的人需要看屏幕的问题、Git 冲突、打包报错
2搜索 + 官方文档90% 的问题都有人问过。搜报错信息的前半句
3Unity 论坛 / 中文社区找了两轮还找不到的
4把问题写成一句话很多问题在写清楚的那一刻就解了

提问模板：

「我想做 X。我试了 Y。结果是 Z（附报错）。我用的是 Unity 版本 A。」
